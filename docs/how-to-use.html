Yosuga Hub の使い方

2026-07-27 時点 / v5 Obsidian ブリッジ

このアプリは何をするか

Hub は考えない。選び・集め・整形し・運ぶだけ。

Yosuga Hub は AI ではない。要約も分類もしない。 やるのは、散らばった情報を確実に運ぶことだけ。

知識の正本は Hub の中ではなく Obsidian の Markdown にある。 Hub はそこへ運び込み、そこから持ち出す。 意味付け（これは何の情報か、どのゲームの話か）は情報を作った側が 出力の時点で済ませておく。だから Hub が読み直す必要がない。

登場するのは3人と、ゲームの数だけの Claude Code

いちばん間違えやすいのがここ。誰が何をするかで、渡す先が変わる。

役正体Hubを読めるか仕事
ヨスガ 通常の ChatGPT（ボイス・メモリあり） 読めない 会話の相棒。相談・設計・アイデア出し。観察日誌とセッション記録を書き、Hub への提案JSONも出す
シロ 人間 — 承認する。運ぶ。知識を活かすのはここ
Claude Code 各ゲームのリポジトリに常駐 — .yosuga/status.json と知識ノートを書く

ヨスガは Hub を読めない。 だから Hub が渡す。ヨスガへ現状報告 を押すと、指示文と現況JSONが そのまま ChatGPT へ届く。要約は挟まない —— 間に要約を挟むと情報が落ちるだけだと分かったため（2026-07-26）。

AI は1体だけ。以前は「Hub を読むAI（レコル）」と 「会話するAI（ヨスガ）」を分けていたが、 レコルは 2026-07-27 に廃止した。 仕分けは生成元（各ゲームの Claude Code / ヨスガ）が出力時点で済ませている。

コマンド何が起きるか
ヨスガへ現状報告 カレンダー取込 → GitHub取得 → Vault書込 → サーバー同期を順に走らせ、 そのまま 指示文 + 現況JSON を ChatGPT へ渡す。 途中で転んでも止まらない（何が転んだかは端末ログに残る）
GitHub → Obsidian 各ゲームの .yosuga/notes/ を取得し、種別ごとに Games/<ゲーム>/ へ振り分けて保存。 更新されたノートは同じ場所へ上書きされる。 取得済みは飛ばし、元が消えたノートは報告だけして残す
会話 → Obsidian ヨスガのセッションまとめを、原文のまま Conversations/Yosuga/ へ
過去情報をヨスガへ ヨスガに渡す資料を作る。現況は既定で入る。 過去ログ（Obsidian のノート）は選んだときだけ足される
回答JSON → Hub 観察日誌でも、セッション記録でも、タスクの提案でも同じ口から入る。 クリップボードに JSON があれば自動で入る
観察日誌を要求 新しい会話が開き、指示文が入力欄に入る。 そのまま送信する。日付は既定で今日 （別の日は会話の中で言えばよい）
ヨスガへ総括を要求 同上。1日の記録（実装・調べたこと・相談・決定・タスク・アイデア・メモ・様子）を JSON で出させ、取り込むと承認を挟まず Obsidian へ入る
REVIEW 承認待ちはここ。承認するまで何もデータに入らない
PROJECTS ゲームの進捗とタスク。「GitHubからすべて更新」もここ
RECORDS アイテム / 決定 / 観測 / 文書 / 関連。分類の確認もここ

1日の流れ

朝に受け取り、日中に相談し、終わりに残す。

  1. 朝：ヨスガへ現状報告 を押す

    カレンダー取込 → GitHub取得 → Vault書込 → サーバー同期が順に走り、 そのまま ChatGPT が開いて指示文と現況JSONが入っている。 送信すればその日が始まる。

    順番に意味がある。カレンダーを最初に置くのは、 ここが古いと最後の同期で古い予定を送ってしまうため。 途中で転んでも止まらない（何が転んだかは端末ログに残る）。

  2. ヨスガが今日の入り口を作る

    昨日の成果（完了タスクと各ゲームの修正を分けて）、今日の予定、 気をつけること（締切が近い・止まっている・詰まりが長い）、シロさんの状態。 長い一覧は読み上げず、その日いちばん効くことを2〜3点だけ。

    指示文は Hub が毎回同梱する。 ChatGPT のメモリに覚えさせる必要はない（2026-07-27〜）。

  3. 制作しながら相談する

    過去の設計判断を思い出したくなったら 過去情報をヨスガへ。 現況に加えて、Obsidian のノートを選んで一緒に渡せる。

  4. 夜：観察日誌を要求 / ヨスガへ総括を要求

    どちらも新しい会話が開き、指示文が入力欄に入っている。 材料（今日やったこと）を伝えて送信する。返ってきた JSON を 回答JSON → Hub へ（共有シートからでも入る）。

    観察日誌は REVIEW で承認して Hub に入る。 セッション記録は記録そのものなので承認を挟まず Conversations/Yosuga/ へ直接入る。

夜は毎回「新しい会話」になる

朝も夜も、Hub は 共有インテントで ChatGPT へ本文を渡している。 長さの制限が実質無い（約1MBまで）代わりに、 行き先の会話を指定できない。だから夜のボタンを押すと、 指示文の入ったまっさらな新しい会話が開く。

渡し方入る量会話の指定
共有インテント 約1MB（いま使っている方） できない
URL の ?q= 日本語 約200字 できる

指示文は 640〜1434 文字あるので URL には載らない。つまり 「入力欄に必ず入ること」と「会話を指定できること」は両立しない。 2026-07-27 に前者を選んだ。

材料は、その新しい会話であなたが話した内容。 朝からの会話の続きではない。ヨスガには 「材料が無いなら書き始めず、一度だけ聞き返す」と毎回指示しているので、 何も渡さずに送ると今日は何がありましたかと聞き返してくる。 それが正しい動き（黙ってそれらしい日誌を作らせない）。

SETTINGS →「ヨスガの会話（退避用）」は、 ChatGPT アプリが入っていない端末向けの逃げ道。ふだんは使わない。

取り込みと承認

AI の出力はそのままデータにならない。必ず承認を挟む。 

AI が JSON を出す
   ↓  共有シート → Yosuga Hub  /  回答JSON → Hub に貼る
承認待ちに入る
   ↓  REVIEW で1件ずつ見る
承認 → データに入る   棄却 → 履歴に残って消える

行き先

種類承認すると
itemsRECORDS のアイテムへ。targetNote があれば Obsidian のノートへ追記
diaryRECORDS の「観測」へ。同じ日付は上書き(一日につき1件)
tasksPROJECTS のタスクへ
directives承認したものだけ各ゲームの Claude Code へ配信
classifications承認待ちを通らない。文書へ直接あたり「確認待ち」に。確定は RECORDS の「文書」で

Vault が未設定だと targetNote の追記は黙って飛ばされる。 Obsidian に入れるつもりなら、先に SETTINGS で Vault を選ぶ。

最初に設定するもの

どれも SETTINGS の中。入れないと動かない機能がある。

設定入れないと
Obsidian Vaultノートの保存も取り出しもできない。共有ストレージ上に置くこと
GitHub トークンゲームの進捗もノートも取得できない
サーバー同期レコルが Hub を読めない。Morning Brief が作れない
レコルのURLレコルを開く が出ない（それだけ）

プロジェクトは PROJECTS →「プロジェクトを追加」で作る。 ID は後から変えられない。 サーバー・レコル・分類履歴がこの ID を見ているため。

うまくいかないとき

症状見るところ
ノートが0件 プロジェクトが登録されているか。リポジトリを上げただけでは Hub は見に行かない。 .yosuga/notes/ が push されているかも確認する
読み取れませんでした JSON が壊れている。説明文が混ざっていても JSON があれば通るはず
Brief が古い 手順1の同期が届いていない。SETTINGS の「今すぐ同期」を押してみる
レコルが聞き返す Instructions が古い。docs/recoru_prompt.md を貼り直す
予定が0件 端末に同期済みのカレンダーを読む方式。アカウントと READ_CALENDAR の許可が要る

消す操作の前に、何が消えるか確かめる。 以前、仮データの削除で実際に使っていたプロジェクトが消え、 全ゲームの取り込みが止まったことがある。

覚えておくと迷わないこと

  • 知識の正本は Obsidian。Hub は通り道であって保管庫ではない。
  • Hub は判断しない。分類も要約も、情報を作った側が済ませておく。
  • 承認しないと入らない。AI が出しただけでは何も起きない。
  • 先にアプリ、あとで AI。順番を逆にすると古いデータを読ませる。
  • 観察日誌はヨスガ、仕分けはレコル。逆はしない。

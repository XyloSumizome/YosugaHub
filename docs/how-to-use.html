Yosuga Hub の使い方

2026-07-25 時点 / v5 Obsidian ブリッジ

このアプリは何をするか

Hub は考えない。選び・集め・整形し・運ぶだけ。

Yosuga Hub は AI ではない。要約も分類もしない。 やるのは、散らばった情報を確実に運ぶことだけ。

知識の正本は Hub の中ではなく Obsidian の Markdown にある。 Hub はそこへ運び込み、そこから持ち出す。 意味付け（これは何の情報か、どのゲームの話か）は情報を作った側が 出力の時点で済ませておく。だから Hub が読み直す必要がない。

登場するのは3人と、ゲームの数だけの Claude Code

いちばん間違えやすいのがここ。誰が何をするかで、渡す先が変わる。

役正体Hubを読めるか仕事
ヨスガ 通常の ChatGPT（ボイス・メモリあり） 読めない 会話の相棒。相談・設計・アイデア出し。観測日記を書く
レコル カスタムGPT + Actions 読める 情報の仕分け。Morning Brief の作成。文書の分類
シロ 人間 — 承認する。運ぶ。知識を活かすのはここ
Claude Code 各ゲームのリポジトリに常駐 — .yosuga/status.json と知識ノートを書く

ヨスガは Hub を読めない。 だから朝の Morning Brief が要る。レコルが Hub を読んで要約し、 それを人間がヨスガへ貼る。この橋渡しが仕組みの背骨。

コマンド何が起きるか
GitHub → Obsidian 各ゲームの .yosuga/notes/ を取得し、種別ごとに Games/<ゲーム>/ へ振り分けて保存。 更新されたノートは同じ場所へ上書きされる。 取得済みは飛ばし、元が消えたノートは報告だけして残す
会話 → Obsidian ヨスガのセッションまとめを、原文のまま Conversations/Yosuga/ へ
ヨスガへ共有 ヨスガに渡す資料を作る。現況は既定で入る。 過去ログ（Obsidian のノート）は選んだときだけ足される
回答JSON → Hub レコルの整理でも、ヨスガの観測日記でも同じ口から入る。 クリップボードに JSON があれば自動で入る
レコルを開く レコル（カスタムGPT）をブラウザで開く。URL は設定で登録する
REVIEW 承認待ちはここ。承認するまで何もデータに入らない
PROJECTS ゲームの進捗とタスク。「GitHubからすべて更新」もここ
RECORDS アイテム / 決定 / 観測 / 文書 / 関連。分類の確認もここ

1日の流れ

朝に受け取り、日中に相談し、終わりに残す。

  1. アプリを新しくする

    PROJECTS →「GitHubからすべて更新」。 各ゲームの進捗が入り、成功するとサーバーへ自動で送られる。

    順番が逆だと意味がない。 先にレコルへ聞くと、古いデータを読ませることになる。

  2. レコルに Morning Brief を作らせる

    レコルを開く →「Morning Brief」と言う。 昨日の成果・今日の予定・未完了タスク・決定事項・課題が Markdown で返る。

  3. ヨスガに貼って1日を始める

    Brief をコピーしてヨスガの会話に貼る。 これでヨスガは今日の状況を知った状態で会話に入れる。

  4. 制作しながら相談する

    過去の設計判断を思い出したくなったら ヨスガへ共有。 現況に加えて、Obsidian のノートを選んで一緒に渡せる。

  5. 終わりに残す

    ヨスガに「セッションまとめをください」→ 会話 → Obsidian で原文を保存。 レコルへ貼れば、タスクや決定事項として整理される。

    「観測を書いて」と言えば観測日記の JSON が返る。 回答JSON → Hub へ。翌朝の Brief の「シロの状態」になる。

レコルの巡回

レコルは合図を待たない。会話を開いて何か一言（「おはよう」でもいい） 送れば、未整理の文書を全件分類して回答JSONを返す。

「Morning Brief」と言ったときだけは Brief を優先する。 同じ会話の2回目以降は巡回しない。

「未整理の文書はありません」は正常。 巡回が見るのは RECORDS → 文書 に手で入れたものだけ。 ゲームの修正は Obsidian へ直行するので、ここには来ない。 何も無い日のほうが多い。

取り込みと承認

AI の出力はそのままデータにならない。必ず承認を挟む。 

AI が JSON を出す
   ↓  共有シート → Yosuga Hub  /  回答JSON → Hub に貼る
承認待ちに入る
   ↓  REVIEW で1件ずつ見る
承認 → データに入る   棄却 → 履歴に残って消える

行き先

種類承認すると
itemsRECORDS のアイテムへ。targetNote があれば Obsidian のノートへ追記
diaryRECORDS の「観測」へ。同じ日付は上書き(一日につき1件)
tasksPROJECTS のタスクへ
directives承認したものだけ各ゲームの Claude Code へ配信
classifications承認待ちを通らない。文書へ直接あたり「確認待ち」に。確定は RECORDS の「文書」で

Vault が未設定だと targetNote の追記は黙って飛ばされる。 Obsidian に入れるつもりなら、先に SETTINGS で Vault を選ぶ。

最初に設定するもの

どれも SETTINGS の中。入れないと動かない機能がある。

設定入れないと
Obsidian Vaultノートの保存も取り出しもできない。共有ストレージ上に置くこと
GitHub トークンゲームの進捗もノートも取得できない
サーバー同期レコルが Hub を読めない。Morning Brief が作れない
レコルのURLレコルを開く が出ない（それだけ）

プロジェクトは PROJECTS →「プロジェクトを追加」で作る。 ID は後から変えられない。 サーバー・レコル・分類履歴がこの ID を見ているため。

うまくいかないとき

症状見るところ
ノートが0件 プロジェクトが登録されているか。リポジトリを上げただけでは Hub は見に行かない。 .yosuga/notes/ が push されているかも確認する
読み取れませんでした JSON が壊れている。説明文が混ざっていても JSON があれば通るはず
Brief が古い 手順1の同期が届いていない。SETTINGS の「今すぐ同期」を押してみる
レコルが聞き返す Instructions が古い。docs/recoru_prompt.md を貼り直す
予定が0件 端末に同期済みのカレンダーを読む方式。アカウントと READ_CALENDAR の許可が要る

消す操作の前に、何が消えるか確かめる。 以前、仮データの削除で実際に使っていたプロジェクトが消え、 全ゲームの取り込みが止まったことがある。

覚えておくと迷わないこと

  • 知識の正本は Obsidian。Hub は通り道であって保管庫ではない。
  • Hub は判断しない。分類も要約も、情報を作った側が済ませておく。
  • 承認しないと入らない。AI が出しただけでは何も起きない。
  • 先にアプリ、あとで AI。順番を逆にすると古いデータを読ませる。
  • 観測日記はヨスガ、仕分けはレコル。逆はしない。

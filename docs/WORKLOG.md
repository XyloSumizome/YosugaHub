### 指示文をメモリから Hub 同梱へ移した

**なぜ**: それまでヨスガの役割・現況の読み方は **ChatGPT のメモリ**に持たせていた。
だがメモリは **中身を確かめられず・いつ薄れたか分からず・新しい会話では効き方が違う**。
実際 2026-07-26 の宿題は「メモリを貼り直す(やらないと翌朝ズレる)」だった。

v5 の「Hub は判断せず、選び・集め・整形し・**運ぶ**」に照らせば、
**指示文もまた運ぶべき情報**でしかない。

- 新規 `data/prompt/YosugaPrompt.kt`(純粋ロジック)。
  `MORNING_HEADER` / `diary(date)` / `session(date)` / `withMorningHeader(json)`
- `> 朝の準備` は **指示文 + 現況JSON** を送るようになった

  「文体はメモリ側が正・二重に書かない」と決めているため。

### 夜のボタンを2つ足した

`> 観測日記を頼む` / `> セッション記録を頼む`。日付は**既定で今日**、
別の日がほしいときは会話の中で言えばヨスガが差し替える(Hub 側にピッカーは置かない)。

**⚠ `?q=` には載らなかった。** ここが今回いちばん実測が効いた点。

| 指示文 | 素 | URL化 | `?q=` |
|---|---|---|---|
| 朝の前置き | 1,222字 | 7,290字 | ✗ |
| 観測日記 | 447字 | 2,373字 | ✗ |
| セッション記録 | 1,246字 | 6,566字 | ✗ |

日本語は URL エンコードで **1文字9バイト**になる。
2026-07-26 にレコルで「巡回」が入力欄に入っていたのは、**2文字だったから**。
仕組みの限界ではなく寸法の話。

→ ボタンは**必ずクリップボードへ入れてから**会話URLを開く。長押しして貼るだけ。
`ChatGptLink` は上限超過時に **`q` を付けずに開く**(切れた指示文を渡すより安全。

**なぜ会話URLが要るのか**: 観測日記もセッション記録も**材料はその日の会話そのもの**。

## 2026-07-25: Vault を「整理されて更新されていく」形にする

### きっかけ(シロさんの指摘)

「GitHub → Obsidian で更新・修正・削除はどう反映されるの?」と聞かれ、調べた答えが
**修正は枝番で二重に増え、削除は放置**だった。希望は「整理されて更新されていく仕組み」。

運用の前提も確認できた:

1. **GitHub のノートは Claude Code だけが書く**。人が Obsidian 側で直すことはない
2. **観察日記は同じ日付が来たら上書き**でよい(一日につき1件の規則)
3. **セッションログは上書きせず無尽蔵に追加**。ただしタグ・カテゴリ分けが必要

「人が手を加えない」が確定したので、旧設計の「上書きしない(人のノートを壊さないため)」
という前提が外れた。

### 1. GitHub ノート: 同じ元ファイルは同じ場所へ上書き

- `ImportedNoteDao.findBySource(projectId, sourcePath)` — sha が変わっても
  **sourcePath が同じなら「更新されたノート」**と判る(記録は元からあった。使っていなかっただけ)
- `VaultWriter.overwrite(vaultPath, content)` — 記録済みの場所を新しい版で丸ごと置換
  ("wt" = truncate)。ファイルが無ければ作る(手で消されていた場合の復元)
- 記録は新しい sha へ置き換え、**場所は据え置き**(同じ元ファイルは同じ場所に居続ける)
- 取り込み結果に「更新 N件」を出す(端末ログは `UPDATE` 行)

**削除は報告のみ。** 一覧の全パス(`listedPaths`)と記録を突き合わせ、
記録にあるのに一覧に無いノートを「リポジトリから消えたノート(Vault側は残しています)」
として列挙する(端末ログは `GONE` 行)。**Vault 側は消さない**——Vault はシロさんと
Obsidian の領分で、消すかどうかは人が決める。記録も消さないので次回も報告される。

### 2. 観測日記: 同じ日付は差し替え

`DiaryRepository.add` が `findByDate` で既存を引き、あれば **body だけ差し替える**。
id と createdAt は初版を引き継ぐ(いつ最初に書かれたかを失わない)。
手動追加も同じ経路なので、同日の書き直しはどこから来ても1件に収まる。

### 3. セッションログ: ヨスガに札(Frontmatter)を付けさせる

追加は従来どおり無尽蔵(上書きしない)。整理は **v5 の原則どおり生成元がやる**:
`yosuga_prompt.md` のセッションまとめに Frontmatter
(`date` / `games` / `category` = game-dev・chat・mixed / `tags`)を必須にした。
Hub は既に「Frontmatter 付きなら包み直さない」実装なので、**アプリ側の変更はゼロ**。
「ゲームの話が無い日は games を空にし category を chat に(無理に結びつけない)」も明記。

### ゲーム側の規則も更新

`claude_code_onboarding.md` の「一度 push したノートを書き換えない」を撤廃。
**訂正・追記は書き換えてよい**(Hub が上書き反映する)。
消した場合は報告だけされること、消すかはシロさんの判断であることを明記。

### テスト

**385件 通過**(381 → +4)。
- 更新されたノートが write でなく overwrite で記録済みの場所へ行く / 記録が新 sha に置き換わる
- 消えたノートが missing に列挙され、記録も Vault も消えない
- 日記の同日差し替え(id・createdAt の引き継ぎ)/ 別日は並存

Room スキーマ変更なし(クエリ追加のみ)。実機未確認。

## 2026-07-25: 共有シートで回答JSONを受ける(貼り付けをやめる)

### やりたいこと

「レコルの回答を貼り付ける」手数をなくしたい。シロさんの案は2つ:

- A. JSON を端末の任意の場所に保存 → 起動時に自動読み込み
- B. クリップボードがレコルのものだったら、起動時に自動で取り込む

### 検討: B は Android の制約で割に合わない

**Android 12 (API 31) 以降、アプリがクリップボードを読むたびに
システムが「◯◯ が △△ からコピーしたテキストを貼り付けました」トーストを出す。**
抑制する API は無い。targetSdk 35 なので確実にかかる。
起動時に毎回読む設計だと、**起動のたびにトーストが出る**。

さらに「レコルのものか」を判定するには**まず読む**必要があるので、
無関係な文字列(パスワード等)も一度は読むことになる。
個人用アプリなので実害は本人だけだが、設計として気持ちがよくない。

判定自体は堅くできる(`ResponseImporter.parse` が通るか)ので、
**やるなら「起動時に自動」ではなくボタンで**、というのが結論。

### 検討: A は入り口が重い

SAF で受け取りフォルダを選ばせ、起動時に未取込 JSON を取り込む。
実装は `SafVaultReader` のパターンで素直。
ただし **ChatGPT アプリから JSON をファイルとして保存するのはコピーより手数が多い**。
PC 経由の運用なら有効だが、スマホ主体では割に合わない。

### 採ったもの: C(共有シートで受ける)

ChatGPT で回答を **共有 → Yosuga Hub**。Android で一番素直な経路。

- アプリを開く操作が要らない(共有先に直接出る)
- トーストなし・権限なし・**サーバー変更なし**
- 先に決めた `PULL INBOX`(人が1回押す)と手数がほぼ同じで、`inbox.php` を作らずに済む

### 実装

**1. JSON の抜き出しを広げた**(`data/file/PastedJson.kt`)

いままでは**先頭が ``` のときだけ**囲いを外していた。共有ではメッセージ全文が来るし、
そもそも**「巡回」は JSON の後ろに実行報告を書く**ので、この形が必ず来る。
「文中から最初の JSON を抜き出す」方式へ変更した。

- 先頭が `{` なら**囲いを探しに行かない**。
  本文に ``` を含む JSON(指示書の body など)を壊さないための順序。
- 囲いが複数あるときは **`{` で始まるブロックを優先**(説明用のブロックを拾わない)。
- 囲いが無ければ、最初の `{` から**対応する** `}` まで。
  文字列リテラルの中の `}` とエスケープされた `"` を数え違えない。
- 閉じていなければ**原文のまま返す** → 解析側が「JSONの形式が正しくありません」で弾く。

**2. 共有を受ける**

- `AndroidManifest.xml`: `ACTION_SEND` / `text/plain` の intent-filter。
  `launchMode="singleTop"` にして、起動済みなら `onNewIntent` で受ける
  (新しい画面を積まない)。
- `SharedText.kt`: 受ける条件の判定。`Intent` は素の単体テストで動かないので、
  **素の値を取る `from(action, type, text)` に中身を寄せて**テストできるようにした。
- `MainActivity`: `StateFlow` で保持し、取り込むか捨てるまで残す。
- `YosugaHubApp`: 共有が届いたら**コンソールへ戻す**
  (サブ画面を開いたまま共有されると気づけないため)。
- `ConsoleScreen`: `SHARED` 確認ダイアログ(先頭600文字のプレビュー + 文字数)。
  共有を選んだ時点で意思表示はあるが、**取り込みは後戻りしにくい**ので一度だけ見せる。

**中身の検査はダイアログでしない**。レコルの回答かどうかは取り込み側の
`ResponseImporter` が判定し、違えばエラーメッセージになる。UI で二重に判定しない。

### つまずいた点

`text/*` を KDoc に書いたらビルドが落ちた。
**Kotlin はブロックコメントが入れ子になる**ので、`/*` が内側のコメントを開き、
`*/` がそれを閉じて外側が閉じないまま残る。「text 系 MIME」と書き換えた。

### 承認フローは変えていない

共有で入るのは**取り込み**まで。そのあとの承認(REVIEW / 文書画面)は従来どおり。
「提案→承認→保存」の方針は崩していない。

### テスト

`assembleDebug` + `testDebugUnitTest` 成功。**375件 通過**(359 → +16)。

- `PastedJsonTest` +10: 報告が後ろに付く形 / 説明文が前に来る形 / 囲い無しの地の文 /
  ブロックが複数 / 入れ子の波括弧 / 文字列内の `}` / エスケープされた `"` /
  本文に ``` を持つ JSON / 閉じていない JSON / JSON が無い文
- `SharedTextTest` +6: text 系のみ受ける / 通常起動を無視 / `SEND_MULTIPLE` を無視 / 空を無視

**実機未確認**。ChatGPT アプリの共有シートに Yosuga Hub が出るか、

## 2026-07-25: レコルに「巡回」を作る(合図ひとつで分類まで済ませる)/ プロンプトのみ

### やりたいこと(シロさんの言葉)

> 「〇〇して」「▽▽して」とやってほしい事を全部頼むんじゃなくて、
> レコルがサーバーからデータを取得したらやるべきことを全て済ませて、
> jsonを保存するところまで自動でやらせたい

### 分けて考える(2つある)

| | 中身 | この回 |
|---|---|---|
| A. 一言で全部やる | 読取 → 全件分類 → items 整形 → 回答JSON | **やった**(プロンプトのみ) |
| B. 保存まで自動 | レコルがサーバーへ回答JSONを POST | **未実装**(下記) |

A はプロンプトの書き換えだけで済む。**サーバーも Android も変更なし**。
B は書き込み口が要るので、A を実レコルで確かめてから作る(段階を分けた)。

### 前提として確かめたこと

- レコルが呼べる Actions は `server/openapi.yaml` の **GET `getYosugaFile` だけ**。
  保存する口は存在しない。
- **`upload.php` を流用してはいけない**。あれは `files[]` の名前で `data/*.json` を
  丸ごと上書きする(`server/upload.php:44`)。レコルに渡すと、名前を間違えた瞬間に
  `projects.json` が回答JSONで潰れる。B では**別ディレクトリ・追記のみ**の口を作る。
- レコルはカスタムGPTなので**自分からは動かない**。「取得したら自動で」の起点は
  シロさんの一言。ここは無人にできない(Hub に AI は載せない方針なので Hub からも起こさない)。
  実現できるのは「**一言 → 全部済んで保存まで**」まで。

### v5 方針との関係

v5 は「意味付けは生成元の Claude Code が出力時点で行い、Hub は分類し直さない」。
今回はレコルの分類を強化する向きなので**逆に見える**が、
**`documents`(手で入れた未整理文書)は Claude Code を通らない**ので、
ここだけはレコルにしかできない。プロンプト冒頭にその但し書きを足した。
併せて「**Claude Code が出したものをレコルが分類し直してはいけない**」も明記。

### 決めたこと(シロさんの選択)

1. 取り込みの自動度 … **`PULL INBOX` を人が1回押す**。承認は従来どおり残す。
2. 自動の範囲 … **分類 + items 整形まで**。
3. 進め方 … **プロンプト先行**。

### 書いたもの(`docs/recoru_prompt.md`)

合図は **「巡回」**(「整理して」「いつもの」も同義)。手順:

1. `file=index` で updatedAt を見る
2. **毎回読むのは `documents` / `knowledge` / `projects` の3つだけ**
   (knowledge は既存タグ・既存ノート名の語彙。読ませないと targetNote が乱造される)
3. `pendingClassification[]` を **1件残らず**分類
4. 参照する価値があるものだけ `items[]` へ。**1文書につき多くて1〜2件**

## 2026-07-25: `[x]` チェックの当たり判定を 48dp へ

### 問題

`TerminalCheckbox` は Material の箱をやめて **`[x]` という文字**で描いている。
見た目は狙いどおりだが、**押せる範囲が文字の大きさそのもの**になっていた。

- 等幅3文字 ≒ 24dp + 上下 4dp のパディング → だいたい **24×24dp**。
- Material の推奨は 48dp。**半分**しかない。
- 特に痛いのが `ProjectDetailScreen` の `TaskRow`。ここは `label = ""` の
  **箱だけ**で使っているので、ラベルで稼ぐ逃げ道もない。
  タスクの完了を切り替えるたびに小さな的を狙わされる。

実機で確かめる前に直せる種類の問題なので、先に直した。

### 直し方

`TerminalToggle.kt` の `TerminalCheckbox` に `defaultMinSize` を一行足しただけ。

```kotlin
private val MinTouchTarget = 48.dp
...
    .then(if (enabled) Modifier.clickable { onCheckedChange(!checked) } else Modifier)
    .defaultMinSize(minWidth = MinTouchTarget, minHeight = MinTouchTarget)
    .padding(vertical = 4.dp),
```

- `clickable` を **`defaultMinSize` より先**に置いているので、
  当たり判定は広げたあとの 48dp 全体になる。逆順だと文字のままになる。
- **文字は大きくしない**。`[x]` の見た目は 1px も変わらない。広がるのは押せる範囲だけ。
- ラベル付きの使い方(設定画面の「プロジェクトも削除する」)では
  横幅はもともと 48dp を超えているので、**効くのは縦だけ**。行が少し高くなる。

### 副作用(実機で見てほしいところ)

`TaskRow` は箱だけなので、**横も 48dp になる**。`[x]` は左端に置いたまま
(等幅の列を揃えたいので中央寄せにはしなかった)なので、
**`[x]` とタスク名の間に 24dp の隙間**が空く。

コンソールUIの余白としては筋が通ると判断したが、
実機で見て広すぎるなら **箱だけのときは `minWidth` を戻し、縦の 48dp だけ残す**。

### やっていないこと

- **`TerminalChip` は触っていない**。こちらも縦 ≒ 24dp と小さいが、
  絞り込みのチップは横に何個も並ぶので、48dp にすると行が厚くなりすぎる。
  実機で押しにくかったら考える。

### テスト

`assembleDebug` + `testDebugUnitTest` 成功。**359件 通過**(件数の増減なし)。
`TerminalCheckbox` に単体テストは無い(Compose のレイアウトなので実機で見る)。

## 2026-07-24: GitHub取得のあとに自動でサーバー同期する

### 問題

`GitHub取得 → Hub → ロリポップ → レコル` は繋がっていたが、
**自動同期は「回答JSONの取り込み成功時」の1箇所だけ**だった(`AppContainer.kt`)。

### 直し方

- `refreshAll()` = 一括更新。**1件でも成功したら、最後に1回だけ**同期する
  (送るのは毎回スナップショット全体なので、件数分呼ぶ意味がない)
- 戻り値を `StatusRefreshResult(fetch, sync)` / `StatusRefreshAllResult(fetches, sync)` にして、
  同期の結果を UI まで持ち上げた。**黙って同期して黙って失敗する**のを避けるため

### 見え方

- Toast: 取得結果の下に「サーバーへ反映しました。」/ 失敗時は
  「設定の『今すぐ同期』でやり直せます。」を足す。
  **同期未設定のときは何も言わない**(未設定は失敗ではない)。
  取り込み時と同じ文面を `ui/share/SyncMessage.kt` の `autoSyncSuffix()` に集約し、
  `ImportMessage` からも使うようにした。
- プロジェクト詳細の端末ログ: GITHUB FETCH の後に
  `> SYNC lolipop` / `  PUSH 7 files … OK` が流れる。未設定なら行自体を出さない。

レコルの役目は **Obsidian への入力を自動化して、2人が参照しやすくすること**。

`knowledge.json` を GitHub 由来のノートで膨らませる必要はない。

### エミュレータの黒画面: 真因はスナップショットだった

`-gpu swiftshader_indirect` で直ったので描画方式が原因かと思ったが、**違った**。

- このバージョンの emulator は `swiftshader_indirect` を**無効な値として拒否**し `auto` に戻す

- `auto`(ホストGPU)のままコールドブートしたら**正常に描画された**

つまり効いていたのは `-no-snapshot-load`(コールドブート)のほう。
`fastboot.forceFastBoot=yes` によるスナップショット復元で、Android が壊れた状態から起き上がっていた。

**最終的な AVD 設定**(`~/.android/avd/Pixel_10.avd/config.ini`、変更前は `.bak-before-gpu-change`):

```
hw.gpu.mode=auto              ← 描画は速いまま
fastboot.forceColdBoot=yes    ← 毎回コールドブート(黒画面の真因を潰す)
fastboot.forceFastBoot=no
vm.heapSize=512               ← 228 から引き上げ
```

この設定で起動15秒・描画正常を確認済み。

## 2026-07-23: GPT Actions からの取得に成功 — v4 の AI 連携が実際に成立

`file=index` の呼び出しが成功し、7ファイルの一覧を ChatGPT 側で取得できた。

### 経路の確定

```
Yosuga Hub --(POST + X-Yosuga-Token)--> upload.php --> data/*.json
                                                          |
ChatGPT (カスタムGPT + Actions) --(GET + X-Yosuga-Token)--> api.php
```

通常のチャットのブラウズは検索インデックス経由で到達できなかったが、

- GPT Actions のバリデータは OpenAPI より厳しい:
  `openapi` は 3.1.0/3.1.1 のみ / `description` は300字以内 /

トークンを**ヘッダーで渡せるようになった**ため、URLに載せる必要がなくなった

- `Document` に `classificationHistory` を追加。DAOは元々 @Relation で全分類行を取得しているため
  追加コストなし。履歴が Flow で流れるので、修正承認するとダイアログの表示も追従する

## 2026-07-23: カレンダー連携(旧Phase 4)— 端末カレンダー読み取りで実装

### 方式の決定(ユーザーと合意)

設計書v2は Google Calendar API + OAuth 前提だったが、**CalendarContract で端末に同期済みの
カレンダー(Googleカレンダー含む)を直接読む方式**を採用した。

- 採用理由: READ_CALENDAR 権限のみで動作し、**Google Cloud プロジェクト / OAuth クライアントID /
  SHA-1登録 / 同意画面の設定がすべて不要**。新規ライブラリもゼロ。オフラインでも動く。
  設計書の完了条件(過去7日〜未来7日を確認 / 状況JSONへ出力)は満たせる。
  「初期版の権限は可能な限り読み取り専用に限定する」(設計書5.1)にも合致。
- 制約: 端末に同期されているカレンダーのみが対象(Pixel で Google カレンダーを使う運用なら問題なし)。
- 将来 API + OAuth へ移す場合も、DataSource を差し替えるだけで済む構造にしてある。

### 新規ライブラリ

- **なし**

### 実施内容

- `AndroidManifest.xml` に **READ_CALENDAR**(読み取り専用)を追加
- `data/calendar/EventFormatting`(純粋ロジック): 今日の日付表示 / 予定時刻の整形
  (今日は時刻のみ・他日は日付+時刻・終日は日付のみ)/ 今日・今後・過去のバケット判定
- `data/calendar/DeviceCalendarDataSource`: `CalendarContract.Instances` を期間指定で問い合わせ
  - **Instances を使うことで繰り返し予定が期間内の個別予定として展開される**
  - 権限チェック、タイトル空欄は「(タイトルなし)」、終日予定は終了時刻を出さない
  - 結果は `Result<List<CalendarEventEntity>>`(例外を投げない)
- `CalendarEventDao.replaceAll()`(@Transaction で全削除→挿入。同期は常に洗い替え)
- `CalendarRepository` を刷新:
  - `today` を**端末時計から**算出(固定文字列のプレースホルダーを廃止)
  - `sync()`: 権限なし → `PermissionDenied` / 失敗 → `Failed`(**キャッシュは変更しない**)/
    成功 → 洗い替え
- `CalendarViewModel`: `sync()` と `hasPermission()`、同期中フラグ
- `CalendarScreen`: 「端末のカレンダーから更新」ボタン(未許可なら権限ダイアログ →
  許可されたらそのまま同期)。0件時の表示、今日の日付をセクション見出しに表示
- `ui/share/CalendarMessage`: 結果 → 短文(0件と失敗を区別、技術的な例外文は出さない)
- **仮カレンダーのシードを停止**(実データに置き換わったため)。`SampleSeed.events` はテスト用に残す
- テスト: `EventFormattingTest` 5件、`CalendarMessageTest` 4件

### テスト結果

- WSL で `assembleDebug` + `testDebugUnitTest` 成功(BUILD SUCCESSFUL)
- **実機/シミュレーター未検証**: 権限ダイアログ、実際の予定取得、繰り返し予定の展開。
  シミュレーターの場合、Googleアカウント未追加だと予定0件になる点に注意。

### これで仮データはすべて解消

- プロジェクト/タスク/知識ベース: 手動編集・AI提案・GitHub取得で実データ化済み
- カレンダー: 端末から実データ取得(本ステップ)

## 2026-07-23: GitHub連携 3-b Ktor で status.json を取得・検証

### 目的

  `ktor-client-content-negotiation` / `ktor-serialization-kotlinx-json`)
  - 理由: ユーザーと合意した HTTP クライアント。kotlinx.serialization(導入済み)と統合でき、
    エンジン差し替えで MockEngine によるユニットテストが書ける。Android は OkHttp エンジンを使用。
- **ktor-client-mock 3.0.3**(testImplementation): 実通信なしで応答を差し替えるため。
- **kotlinx-coroutines-test 1.9.0**(testImplementation): コルーチンテストの標準ユーティリティ。

### 実施内容

- `AndroidManifest.xml` に **INTERNET 権限**を追加(GitHub 取得に必須)
- `data/github/model/ProjectStatus`: 設計書19.2 の status.json モデル
  (必須は schemaVersion のみ、他はデフォルト値付き。currentGoal / completed / inProgress /
  nextTasks / blockers / recentChanges / risks / decisions / questionsForYosuga)
- `data/github/StatusParser`(純粋ロジック): `ignoreUnknownKeys` で未知項目を無視、
  schemaVersion 検証(1のみ対応)、**projectId の突き合わせ**(設計書20章の必須条件)。
  結果は sealed(Success / InvalidJson / UnsupportedSchema / ProjectIdMismatch)
- `data/github/GitHubApi`: Contents API から `Accept: application/vnd.github.raw` で本文を直接取得
  (Base64デコード不要)。`X-GitHub-Api-Version` 付与、タイムアウト設定、ブランチ指定は `?ref=`。
  HTTPステータスを FetchResult(Success/Unauthorized/NotFound/HttpError/NetworkError)へ分類。
  **例外メッセージを伝播させない**(トークンが載る事故を防ぐ)
- `data/repository/GitHubStatusRepository`: リポジトリ未設定・トークン未設定を**通信前に**判定し、
  取得〜検証結果を `StatusFetchResult` へ集約
  - トークンは `tokenProvider: suspend () -> String?` で受ける(Keystore/DataStore に依存せずテスト可能。
    当初 GitHubSettingsRepository を直接受けていたが、final クラスでフェイク化できず設計変更)
- `AppContainer` に gitHubStatusRepository を配線(tokenProvider は復号関数を渡す)
- テスト: `StatusParserTest` 7件(正常/未知項目無視/最小/壊れたJSON/schemaVersion欠落/非対応版/ID不一致)、

  ref パラメータ、未設定時は通信しない、401/403/404/500/オフライン、JSON異常の分類)

### 詰まった点

- Ktor 3 の MockEngine ハンドラは `MockRequestHandleScope` レシーバが必要で、
  素のラムダ型では `respond` が解決できない。テストの関数型を
  `MockRequestHandleScope.(HttpRequestData) -> HttpResponseData` に修正して解決。

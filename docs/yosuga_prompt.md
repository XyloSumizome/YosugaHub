# ヨスガ用プロンプト(v5: Hub が同梱する)

ChatGPT に「ヨスガ」として振る舞ってもらうための指示文。
**ヨスガはカスタムGPTではなく、通常の ChatGPT**(ボイス・メモリが使える方)。

## ⚠ 2026-07-27: 指示文の置き場所が変わった

**指示文の正本は、このファイルではなく Kotlin のソースになった。**

    app/src/main/java/com/shiro/yosugahub/data/prompt/YosugaPrompt.kt

それまでは、このファイルの内容を貼って「これを覚えて」と言い、
**ChatGPT のメモリ**に持たせていた。やめた理由:

- メモリは**中身をこちらから確かめられない**。効いているのか、薄れたのか分からない
- **いつ更新すればよいか気づけない**。実際 2026-07-26 に朝の経路を変えたとき、
  「メモリを貼り直す」が宿題として残り、やらなければ翌朝ズレる状態になっていた
- 新しい会話・別の端末では、同じようには始まらない

v5 の「Hub は判断せず、選び・集め・整形し・**運ぶ**」に照らせば、
**指示文もまた運ぶべき情報**でしかない。だから毎回 Hub が同梱する。

**このファイルは運用の説明書**であって、貼り付け元ではない。
文面を直したいときは `YosugaPrompt.kt` を直す(直すと `YosugaPromptTest` が守る)。

### メモリに残っているのは1つだけ

**観察日誌の文体規則**(「観察日記 作成ルール」)。
文体・視点・一人称・感情の距離感・禁止表現・内容の選び方は、**メモリ側が正**。

`YosugaPrompt.diary()` は形式(JSONの形・日付・禁止事項)だけを指定し、
文体には触れない。二重に書くと、片方を直したときにもう片方が古くなって食い違うため。

Hub 側へ移したくなったら `YosugaPrompt.DIARY_STYLE` に入れる。
空でなくなった時点で、日記の要求文も自動で同梱に切り替わる(この節も同時に直すこと)。

## 1日の流れ(2026-07-27 時点)

| いつ | コンソール | 何が起きるか |
|---|---|---|
| 朝 | `> ヨスガへ現状報告` | カレンダー取込 → GitHub取得 → Vault書込 → サーバー同期 →<br>**指示文 + 現況JSON** が ChatGPT へ届く。送信すれば始まる |
| 制作中 | — | ヨスガと会話・相談(ボイス可) |
| 夜 | `> 観察日誌を要求` | **新しい会話**が開き、指示文が入力欄に入る。送信すれば書く |
| 夜 | `> ヨスガへ総括を要求` | 同上。1日の記録を JSON で出させる |
| 夜 | `> 回答JSON → Hub` | 受け取った JSON を取り込む(共有シートからでも可) |

### ⚠ 夜は毎回「新しい会話」になる

朝も夜も **共有インテント**(`ACTION_SEND` / `EXTRA_TEXT`)で渡している。
これは長さの制限が実質無い代わりに、**行き先の会話を指定できない**。

    共有インテント   約1MBまで通る   だが会話は選べない(毎回新しい会話)
    URL の ?q=      日本語 約200字   会話は指定できる

指示文は 690〜1490 文字あるので **URL には載らない**。
「入力欄に必ず入ること」と「会話を指定できること」は**両立しない**——
2026-07-27 に前者を取った。

**だから夜の指示文には `NIGHT_HEADER` が必ず付く。**
新しい会話にはヨスガの役割も今日のやりとりも無いので、

- 自分が何者か
- **材料は、この会話ではなく「今日それまでの会話」**(履歴から思い出す)
- **確認の質問から始めない**
- ただし**思い出せないことを作らない**。手元に無い部分は
  「この部分は分かりません」と本文に書く

を毎回同梱する。

### ⚠ 聞き返させない。ただし捏造もさせない

最初は「材料が無いなら一度だけ聞き返す」と書いていたが、実機で毎回
「今日は何がありましたか」と聞かれる形になり、**2026-07-27 に外した**。
材料は目の前の会話ではなく**その日それまでの会話**なので、聞くのではなく
履歴から拾えばよい。

**捏造の禁止だけは残してある。** ChatGPT の履歴参照が効かない設定だと
ヨスガの手元は空になり、それらしい嘘の日誌が出る。しかもセッション記録は
**承認を挟まず Obsidian へ入る**ので、そのまま残ってしまう。
だから「分からないところは分からないと書く」だけは必ず言わせる
(質問とは別物)。`YosugaPromptTest` が両方を守っている——
**質問から始めるなと書いてあるか / 推測の禁止が残っているか**。

`python3 scripts/measure_prompts.py` で寸法を測れる。
⚠ このスクリプトは**名前で**ブロックを取り出す。以前は出てくる順に
決め打ちしていたため、定数を1つ足しただけで全部ずれて別の字数を出していた。

⚠ **行き先の会話を選ぶ設定は無い**(2026-07-27 に一度置いて同日中に撤去)。
共有インテントに変えた時点で、その URL は「ChatGPT アプリが入っていない端末」
でしか読まれず、実質使われない欄になったため。

## Hub が受け取れる JSON

すべて `> 回答JSON → Hub`(または共有シート)から入る。同じ口。

| 鍵 | 何になるか | 承認 |
|---|---|---|
| `diary` | 観察日誌 | REVIEW で承認 |
| `session` | Obsidian の `Conversations/Yosuga/YYYY-MM-DD-session.md` | **なし**(記録そのものなので) |
| `tasks` | タスク | REVIEW で承認 |
| `items` | 知識アイテム(`targetNote` があれば Obsidian へも追記) | REVIEW で承認 |
| `classifications` | 手打ち文書の分類 | 文書画面で承認 |
| `directives` | 各ゲームの Claude Code への指示書 | REVIEW で承認 |

`session` に承認を挟まないのは、**判断の余地が無いものに承認画面を通させない**ため。
中身を読まずに承認するだけの画面は、承認の意味を薄くする。

### セッション記録の Frontmatter は Hub が組む

ヨスガには `date` / `games` / `category` / `tags` / `body` を**構造化して**出させ、
YAML は書かせない。引用符やコロンで壊れた Frontmatter を Obsidian は
**無いものとして扱う**ため、検索から静かに消えるのを防ぐ。

## タグの表記ゆれについて

現況JSONに `vocabulary`(既存のタグ名・エンティティ名)が入っている。
ヨスガはここから選ぶので、**仕分けまで済ませた状態で提案を出せる**。
新しいタグを足すのは、本当に新しい概念が出てきたときだけ。

これが 2026-07-26 に**レコルを挟む理由を失わせた**変更でもある
(レコルが優位だった唯一の点が「既存タグを読めること」だった)。
